# Pandora Main Account UX audit — 2026-10-01

Scope: Pandora's owner/operator web control plane and mobile app. PLP and the
Connections implementation packages are outside this lane. The audit used the
current `main` source at `fb47c7838e7e30d52c2b6e6bf1ef4a33e982b7d4`, a live
local rendering of the web control plane, and fresh Flutter golden captures at
390×844 and 320×800.

## What owners experience today

### Highest-impact findings

1. **The web brand mark is broken.** The header requests a pinned raw GitHub
   image that now returns 404 even though the canonical Pandora mark ships with
   the repository. This affects trust immediately on every route.
2. **The visual language splits at least three ways.** Web owner surfaces,
   porcelain mobile screens, and the newer obsidian mobile shell define their
   own colors and component behavior. Identical concepts such as primary
   actions, focus, cards, and muted text do not have one meaning.
3. **Brand red is doing too many jobs.** It represents identity, primary
   action, focus, progress, and active runtime stages. That weakens status
   semantics and makes routine actions feel urgent.
4. **Decoration competes with operational clarity.** Gradients, glow, blurred
   accents, and grid overlays make dense control-plane pages feel less calm.
5. **Empty states explain absence but often stop there.** Projects and
   unauthenticated connection surfaces contain large unused areas without an
   obvious next action.
6. **The default mobile information architecture is crowded.** The signed-in
   shell exposes a long cross-workspace destination list before establishing a
   clear current organization. A tenant-aware organization switcher should
   become the stable top-level context during onboarding work.

### Accessibility and responsive findings

- Existing 44–48px controls are generally usable, but compact actions fell to
  40px and focus used the same red as branding. The new contract sets 48px as
  the default control target, never below 44px, with an independent focus color.
- Muted text must meet WCAG AA against its actual card surface. Mobile token
  tests now calculate the contrast ratio for both graphite and porcelain.
- Reduced-motion handling already existed in one late stylesheet, but motion
  durations were scattered. Motion is now tokenized and forced-colors behavior
  is explicit.
- The web layout is structurally responsive from 320px through the desktop rail
  breakpoint. The next navigation milestone should reduce destination density
  rather than merely compress it.

### Performance findings

- The failed remote image adds a wasted request and visible layout defect. The
  canonical local asset removes that network dependency.
- The page paints multiple decorative gradients and blurred effects. Removing
  those effects reduces paint work and keeps content stable.
- Font preconnects and explicit image dimensions are already present. A later
  milestone should self-host the critical font subset or use the system stack
  for first paint if field data shows the remote font is material.

## Design-system contract introduced by this milestone

- One semantic token source per platform for color, typography, a 4px spacing
  scale, radii, elevation, layout widths, focus, and motion.
- Warm porcelain and quiet graphite surfaces; solid cards and restrained
  shadows.
- Indigo for routine actions and keyboard focus. Pandora red is reserved for
  identity and critical meaning.
- 48px standard controls, 44px absolute compact minimum, visible 3px focus.
- WCAG AA text contrast, reduced-motion support, and forced-colors support.
- Empty states should explain what happened and provide the safest useful next
  step; implementation continues in the tenant onboarding milestone.

## Prioritized follow-on

1. Add the tenant-aware sign-up and organization creation journey, then land an
   organization switcher as the top-level context on web and mobile.
2. Replace the invite-only post-auth dead end with resumable provisioning states
   covering business type, property/outlet template, and branding.
3. Reorganize navigation around the active organization and progressive
   disclosure; keep advanced operational areas available without front-loading
   them.
4. Connect each organization's onboarding checklist to the published
   Connections Center contract without editing Connections-owned files.
5. Add field performance budgets for first contentful paint and cumulative
   layout shift after the authenticated web path can be exercised in CI.

## Evidence and boundaries

- Fresh mobile before-state evidence was generated by
  `owner_screens_visual_evidence_test.dart` into
  `build/owner-screen-evidence/` before implementation.
- Web Home, Projects, Professional Home, and Professional Connect were inspected
  in a current local browser render at desktop and compact app viewport sizes.
- No PLP surface or Connections-owned package/function is changed by this
  milestone.
- The existing Pandora/Doctora data model is not changed by this milestone.
