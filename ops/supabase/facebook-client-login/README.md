# Facebook identity guard: source-only release candidate

Target PR: #782, original head `b00d1e44de67e44bb908fe563c77c3e9b67c5b44`.

Supabase Auth automatically links Facebook identities with a matching email to existing users before the Before User Created hook runs. The signed hook in #782 restricts new signups. This staged design records an insert receipt only when Auth creates a Facebook user, then consumes it on the first matching Facebook identity in the same transaction. It rejects linking to a preexisting user even if GoTrue updates that user's row, denies another identity, and refuses a different user's matching email. `auth.identities.email` is generated after BEFORE triggers, so the guard reads `identity_data.email`. A rejected identity insert aborts the Auth transaction so no session or second user is committed by that callback. Receipts left by an aborted or interrupted signup cannot pass in a later transaction; monitor and remove stale receipts through a separately authorized cleanup release.

This is staged SQL under `ops/`, not a migration. Do not apply it to production without separate Owner authority. Before enabling the Facebook provider: run the database tests in this PR, get independent exact-head review, deploy this exact guard through an approved database release, read back the trigger/function and run real staging GoTrue OAuth tests for existing confirmed, unconfirmed, no-identity, and new accounts. Verify production collision postconditions in a bounded authorized test, then verify the signup hook and provider settings. If GoTrue changes transaction behavior, fail closed and keep the provider disabled. Rollback begins by disabling the Facebook provider; dropping the guard requires a separately reviewed release. No Page or ads connection is touched.
